# V8.4：单模型四角检测

2026-09-06。当前默认算法为 V8.4，Python 软件包版本为 0.2.0，确认界面保持 GUI 2.0。入口见 [README](../README.md)，版本历史见[变更日志](../CHANGELOG.md)。

## 主流程

单个 MobileNetV3 网络预测四条边的位置分布和支持程度，用自身位置方差加权拟合边线，再求四角。使用固定的单个 ONNX 模型推理，不调用旧检测器挑选或救回候选。裁剪目标仍是照片内容边界，用户在本机界面确认或调整后进行透视校正。

```bash
photocut input --detect
photocut input --confirm
photocut input --crop
```

每个合法候选都需要人工确认。非法几何和无法获得有效候选的输入不提供可确认、可裁剪坐标，当前界面只能跳过，不夹紧越界坐标来制造合法结果。当前没有自动接受率校准，不能因为模型合法就认为裁剪一定正确。

旧流程通过 `--detector auto` 显式启用；`--detector v8`、`v7`、`v5.2` 保留兼容。`--scene-profile generic_single` 只用于旧 `--detector auto` 流程，不是 V8.4 已验证的场景扩展。

## 证据与限制

严格达标要求四边形合法，且四角最大位置误差不超过图像对角线的 0.5%；严重错误指四角平均误差超过图像对角线的 3%。非法坐标即使误差较小，也不算严格达标。

| 评估 | 对照 | V8.4 训练方案 / 模型 | 配对新增 / 退化 |
| --- | --- | --- | --- |
| 来源分组折外，320 张 | 每折使用可训练来源中的 176 张：291 严格 | 每折使用全部可训练来源：294 严格 | +9 / −6 |
| 已知 320 张适配 | V8.3 research1：306 严格 | 全 320 张训练：314 严格 | +10 / −2 |

两行是不同评估设计，不能互相相减。来源分组使用四个来源代理组，每张照片由未训练该组的模型检测一次；仅四个组和一个随机种子，全部照片也已用于历史研究，因此不是新的独立盲测。折模型用于评价训练方案，不参与最终推理或集成。分组对照非法结果为 7→5，严重错误均为 0。

最终发布一个使用全部 320 张照片训练的模型。其 314/320（98.125%）是训练集适配成绩，不能当成对新照片的泛化准确率。剩余 6 张中，3 张合法但定位误差超标，3 张误差达标但坐标非法；严重错误为 0。两张相对旧模型的退化均为几何非法，保留旧严格结果 304/306。

原研究要求同时达到至少 314 张、保住旧 306 张、非法归零以及子组不退步。本模型只达到数量目标，完整替换条件仍未通过，部分来源仍有退化。维护者明确决定将该版本接入默认人工确认流程；这是部署取舍，不改变原实验结论，也不宣称角点问题已经全部解决。

下一轮仍以来源分组对照和配对退化为依据，检查目标边界监督及真实场景覆盖，保持一个最终模型。不能以最终训练集分数替代来源外验证。

## 部署核对

导出的 ONNX 与原训练模型在全部 320 张照片上逐张比较：两者均为 314 张合法严格、3 张非法、0 张严重错误；严格和合法判定没有分歧，最大坐标差约为图像对角线的 1.663×10⁻⁶。这验证导出的一致性，不增加泛化证据。

已构建 wheel 与源码包并检查模型资产；在临时虚拟环境安装 wheel 后，合成照片完成实际 ONNX 推理、纯色图被拒绝。该环境复用已有数值依赖，并明确拦截 Torch / TorchVision 导入，实际推理没有加载二者。此核对不等同于已在所有支持的操作系统测试。

## 发布边界与许可

公开部署资产位于 `photocut/models/v8_4/`：`model.onnx`、`manifest.json`、`MODEL_NOTICE.txt`、`THIRD_PARTY_NOTICE.txt`。清单记录模型身份和推理契约，安装时无需 PyTorch 或训练数据。旧 V8.2 部署资产继续用于显式回滚。

源码与发布模型按项目 [MIT License](../LICENSE) 提供，TorchVision MobileNetV3 上游 BSD-3-Clause 声明随模型保留。原始照片、标注、训练检查点、来源目录映射、逐图坐标与实验日志留在研究环境，不属于公开部署资产。

## 主流程回归

实际 CLI 到原图坐标和确认控制器的全 320 张核对仍为 314 张严格、3 张非法；GUI 不足 1 像素的整数截断未改变达标成员。全部 317 个合法候选需要确认，未确认结果经实际裁剪入口验证为 0 次裁剪。公开完整测试 834 项、366 个子测试通过；后续续跑及身份拒绝检查也通过。

## 原目录升级与旧确认

同一输出目录从旧检测器重新检测时，新批次保存 V8.4 预测，同时保留已有正式确认边界。旧确认通过显式原批次引用继续修订，修订追加到原标注链；不复制标注 ID，不覆盖历史事件。完整升级、修订、重开恢复和裁剪链路已验证，全库样本数不增加；来源路径或图片身份不匹配时拒绝操作。
